# 多模态历史问答 RAG Agent

面向考古 / 历史领域的图文混合问答系统：输入一道题（题干 + 可选配图），系统自动路由到最合适的检索策略，从历史知识库召回证据，再调用 Qwen2.5-VL 生成归一化答案。覆盖判断、选择、简答三大类共 6 种题型（含带图 VQA）。

> **关于分工**：这是一个团队赛题项目。**我负责检索层与知识库标签部分**——题型路由分发、BM25 混合检索、HyDE 查询扩展、IB 相关性重排、实体抽取与知识库标签体系。生成层的 prompt 工程、评测脚本、前端页面与工程化由队友共同完成。

## 一、赛题背景

赛题要求实现一个端到端 Multimodal RAG Agent：输入 `question` 与可选 `image_url`，结合历史知识库检索结果生成答案，输出归一化后的 `predictions.jsonl` 与耗时统计 `time_cost.jsonl`。评分按题型分别归一化后精确匹配。

难点集中在三处：

1. **领域特殊**——史料文本含大量文言与专名，通用向量检索召回质量不稳定；
2. **模态混合**——VQA 类题目需要同时理解图片与题干，纯文本检索会丢信息；
3. **题型异构**——判断、选择、简答三类题对证据粒度的需求完全不同，单一检索策略无法同时最优。

## 三、检索层的核心设计

**1. 按题型路由（本项目最关键的改动）**

把「一道题该用哪种检索」显式建模成路由问题：判断题优先 BM25 混合检索（判定类证据往往是原文中的一句话，稀疏检索命中更准），简答题走 HyDE + IB 重排（需要语义扩展与相关性过滤），VQA 与选择题走向量检索并保留图片上下文。路由是零侵入的：默认开启，可通过环境变量显式关闭，方便做 A/B 对照。

**2. BM25 hybrid：稀疏 + 稠密 RRF 融合**

用 jieba 分词 + `rank_bm25.BM25Okapi` 在本地构建 5472 段索引，与 DashVector 的稠密检索结果通过 RRF（k=60）融合。稀疏检索弥补了向量检索在专名、数字、引文上的弱点，判断题 VQA 一类做到满分。

**3. HyDE 查询扩展 + IB 相关性重排**

简答题先让 LLM 生成一段「假设性答案」作为检索锚点，再用二分类式的 IB 重排过滤不相关段落，提升上下文质量，而不是一味增加召回数量。

**4. 知识库标签与实体链接**

对语料做领域实体抽取（人物、朝代、器物、地名等）并建立标签体系，用于约束检索范围、消解跨段落指代，也作为知识库维护时的组织维度。

## 四、评测结果

50 题官方评测集（最终版本）：

| 题型 | 题数 | 正确 | 准确率 |
|---|---|---|---|
| 判断 QA | 11 | 10 | 91% |
| 判断 VQA | 9 | 9 | 100% |
| 简答 QA | 4 | 1 | 25% |
| 简答 VQA | 7 | 6 | 86% |
| 选择 QA | 10 | 7 | 70% |
| 选择 VQA | 9 | 7 | 78% |
| **合计** | **50** | **40** | **80%** |

相比 baseline 的 76% 提升到 80%。另外在 120 题分层构造的 mock 集上做泛化验证，总体从 48.3% 提升到 51.7%，其中简答 QA 从 30% 提升到 55%。

代价是耗时增加：50 题从 156s 到 163s（+5%），120 题从 254s 到 311s（+22%），开销主要来自简答路径的多次 LLM 调用。

```
.

├── student_package/

│   ├── data/                   样例数据与配图
│   ├── docs/                   任务、评分与数据格式说明

│   └── frontend/               演示用前端
└── run.sh                      一键运行脚本
```

检索层相关模块（位于 `student_package/solution/`）：

| 文件 | 作用 |
|---|---|
| `router_retriever.py` | 按题型分发检索策略 |
| `hybrid_retriever.py` | DashVector + BM25 的 RRF 融合 |
| `bm25_retriever.py` | jieba 分词 + BM25Okapi |
| `hyde_retriever.py` | LLM 生成假设答案作为检索锚点 |
| `ib_rerank_retriever.py` | LLM 二分类相关性重排 |
| `entity_extractor.py` | 领域实体抽取与标签 |
| `bm25_index.pkl` | 预构建的 5472 段 BM25 索引 |

## 六、运行方式

需要配置自己的 API 凭证（仓库中均为占位符）：

```bash
export QWEN_API_KEY=sk-your-own-key
export DASHVECTOR_API_KEY=sk-your-own-key
export DASHVECTOR_ENDPOINT=<your-dashvector-endpoint>

bash run_eval.sh          # 运行 → 格式校验 → 评分
```

Python 依赖声明在 `student_package/solution/requirements.txt`。

## 七、分支说明

仓库保留了开发过程中的实验分支，用于对照不同检索策略的效果：

- `main` / `try_cls`：最终版本
- `opt-kfirst-d1-d3`、`opt-v4-plus-hyde`：查询扩展与召回优化的对照实验
- `submit`：提交快照
