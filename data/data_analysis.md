# 数据分析报告

> 对象：`data/public_examples.full.json`（公开样例，50 道题）
> 目的：摸清数据形态、识别"得分关键点"和"评测陷阱"，指导后续 RAG Agent 的设计

## 1. 数据规模与题型分布

公开样例共 **50 道题**，分布如下：

| section    | 数量 | 占比  | 是否带图 | 答案形式            |
|------------|------|-------|----------|---------------------|
| 选择QA     | 10   | 20%   | 否       | 大写字母（含多选）  |
| 选择VQA    | 9    | 18%   | 是       | 大写字母（含多选）  |
| 判断QA     | 10   | 20%   | 否       | `正确` / `错误`     |
| 判断VQA    | 9    | 18%   | 是       | `正确` / `错误`     |
| 简答QA     | 4    | 8%    | 否       | 简短文本（2–10 字） |
| 简答VQA    | 8    | 16%   | 是       | 简短文本（1–5 字）  |
| **总计**   | 50   | 100%  | 26 题带图 |                    |

- **VQA 占比 52%**（26/50）：多模态绝不是点缀，而是主战场。
- **简答题占比 24%**（12/50）：填空式短答，归一化非常严格（见 §4），是分数高低关键。
- 隐藏测试集分布大概率与之相近 —— 公开样例的题型比例是隐含的设计提示。

## 2. 领域 / 主题分析

**主题高度聚焦于先秦至汉代的中国考古学**：

- 高频主题：商周青铜器（鼎、簋、甗、铙）、甲骨文与卜辞、墓葬制度（腰坑、单葬墓）、简牍（睡虎地秦简、清华简、上博简）、玉器、瓦当、封泥、铭文释读。
- 高频实体：殷墟、龙山文化、仰韶文化、辛店文化、屈家岭文化、朱开沟遗址、凌家滩、随州叶家山、清华简、散氏盘、作册般甗。
- 时间跨度：从新石器晚期（约公元前 3000 年）到秦汉。
- 几乎不出现：宋元明清、近现代史、世界史。

**结论**：知识库 (DashVector collection `ccv_cb_student_20260508`) 的语料大概率就是中国先秦秦汉考古文献。检索词构造时应**多用考古学术语**（"墓葬形制"、"器型"、"铭文释读"），少用现代白话。

## 3. 各题型逐项分析

### 3.1 选择QA（10 题）

- **特征**：题干通常包含一个非常具体的考古事实点（"湖北朱家台遗址龙山文化陶器口缘特征"、"商代墓葬腰坑动物牺牲"），4 个选项排在题干末尾。
- **多选混入**：10 题里至少 3 题答案是 `AB`、`ABCD` 这类多选 —— 模型若默认单选会丢分。
- **选项格式不统一**：有的 `A.鼎B.罐C.锅D.缸`（无空格），有的 `A. 鼎 B. 罐`，有的中文逗号分隔。**预处理时需要正则规范化**。
- **得分关键**：检索能不能命中"朱家台遗址龙山文化陶器"这一精确句段。

### 3.2 选择VQA（9 题）

- **特征**：题干常以"如图所示"开头，问图中器物属性（纹饰、类型、特征）。
- **典型样例**：
  - "南阳名门华府 M38:14 出土的这件圆形玉片属于哪种玉器类型？" → 答 C "璧芯形器"
  - "偃师商城遗址出土的这件陶鬲的腹部纹饰属于哪种类型？" → 答 A "绳纹"
- **关键发现**：**题干已经给出器物的考古编号或出土地**，所以即使不看图，靠文本检索也能命中相当一部分。图主要起佐证、消歧作用。
- **图的角色**：辅助 > 决定。即使关掉图，VQA 选择题的天花板也比简答VQA 高。

### 3.3 判断QA（10 题）

- **特征**：一句陈述，判 `正确` / `错误`。陈述通常涉及"年代 / 地点 / 人物 / 数量"四类细节之一。
- **观察**：10 题里**错误**占比明显高于随机 —— 出题人倾向于把容易混淆的事实做成错误项。
- **正则陷阱**：[normalization.py:37-43](../src/normalization.py#L37-L43) 的归一化逻辑——如果模型同时输出"正确"和"错误"两个词（如"这句话**不正确**，应该是**错误**"），返回空串 → 0 分。**必须强约束 Prompt**：只输出 `正确` 或 `错误` 二字。

### 3.4 判断VQA（9 题）

- **特征**：陈述往往是"如图所示，X 是 Y" 或"图中 X 描述正确" —— 需要图文交叉验证。
- **典型样例**：
  - 殷墟卜用龟腹甲钻凿排列方式 → 需要看图数排列。
  - 商王世系表中"大乙的妣名" → 需要看图找表格条目。
- **难点**：图常常是**铭文拓片、世系表、地图**，OCR-style 视觉任务。Qwen-VL 在这类细粒度图上是否稳定，需要单独跑通验证。

### 3.5 简答QA（4 题）

- **特征**：填空式短答。Gold 长度 2–10 字。
- 4 个样例的 gold：
  - "相当于流放刑"
  - "该器物名称为铜钾。"
  - "实事求是"
  - "战国中晚期。"
- **观察**：Gold 本身带不带"该器物名称为..."、句末带不带句号都不统一 —— 归一化会消化掉这些。但模型一旦多输出一句解释，第一行之外的内容就丢了。
- **得分关键**：Prompt 必须明确"**只输出最终答案短语，不超过 10 字，不要任何前缀和句号**"。

### 3.6 简答VQA（8 题）

- **特征**：几乎是**纯视觉任务** —— 在图上识字、数数、判断方向、识别物体。
- 8 个样例的 gold：`宝`、`王`、`甲`、`2`、`上`、`链条`、`于`、（铭文识字若干）。
- **关键洞察**：**检索对这类题几乎无帮助**，甚至会引入噪声。这一类题是 Qwen2.5-VL 的视觉理解能力直接打分。
- **设计建议**：对简答VQA **降低甚至跳过检索权重**，直接走 VL 推理。如果做了检索增强反而拖累，要做 A/B 验证。

## 4. 评测归一化的"陷阱地图"

详读 [src/normalization.py](../src/normalization.py) 后总结的**踩坑点**：

| 陷阱 | 触发条件 | 后果 | 防御方式 |
|---|---|---|---|
| 多选无分隔符 + 字典序 | 模型输出 `A、B、D` | 归一化 → `ABD`（OK） | 但模型若说"我选 A 和 D 不选 B"，正则会全部抓出 `ABD`（错） |
| 判断题双关键词 | 模型同时输出"正确""错误" | 归一化返回 `""` → 0 分 | Prompt 强约束 + raw_answer 后处理只保留单一词 |
| 简答取第一行 | 模型先解释再给答案 | 答案被丢弃 | Prompt 要求"第一行就是最终答案" |
| 简答末尾标点 | 输出含 `。、,、!` | 归一化会 rstrip 掉（OK） | 不用刻意去掉 |
| 简答前缀 | "答：是..."、"答案是..." | 归一化会去掉部分前缀 | 仍建议 Prompt 中不要带 |
| 全角/半角字母 | `Ａ` vs `A` | 归一化统一为半角（OK） | 不必担心 |
| 选择题字母后大小写 | `a`、`b` | 归一化转大写（OK） | 不必担心 |

**核心结论**：**严格的输出格式约束（Prompt 工程）能比检索召回多拿出 5%–15% 的分数**。这是性价比最高的一处发力点。

## 6. 隐藏字段警告

公开数据里包含 `expected_answer`，正式评测**不会提供**。代码中**严禁**读取 `expected_answer`、`material`、`think`（详见 [docs/task.md](../docs/task.md)）。check_output.py 也会校验输出不能包含 `expected_answer / material / think / contexts / error`。

## 7. 时间统计要求

`time_cost.jsonl` 是硬性校验项（[scripts/check_output.py:55-79](../scripts/check_output.py#L55-L79)）：
- 行数必须 = 预测行数；
- 每行必须含 `index`、`retrieval_cost`、`infer_cost` 三字段，且后两个是数值类型。

**计时点必须精确**：
- `retrieval_cost`：从构造好 query、准备调 embedding 开始，到 DashVector 返回结果结束（含 embedding + 网络）。
- `infer_cost`：从 `model.generate()` 开始到拿到完整文本结束。

不计入：模型加载、prompt 拼接、图片读取、写文件 IO。

## 8. 几条直接可用的"洞见"

1. **题型分支 Prompt 是最大 ROI 改动**。一套通用 Prompt 同时打 6 种题型必然顾此失彼。最低成本就能把"判断题双关键词"和"简答题多余解释"这两个失分大头消掉。

2. **检索 query 中带选项**。选择题把 A/B/C/D 的选项内容拼进 query，候选答案（如"璧芯形器"、"花边状"）本身就是文献关键词，召回质量会有质变。

3. **简答VQA 应另立流水线**。这 8 道题几乎不需要检索，强行检索反而引入噪声。可以做条件分支：`if section == "简答VQA": skip retrieval`。

4. **判断题的先验是"错误偏多"**。在不确定时，倾向输出"错误"比倾向"正确"期望分数更高（基于公开样例统计；隐藏集需谨慎，但作为兜底是合理的）。

5. **图片描述可以作为 query 增强**。VQA 题先让 Qwen-VL 生成一段"这是一件……，纹饰是……，铭文是……"的描述，把描述拼进检索 query，比只用题干文本检索召回精准。

6. **多 query / HyDE 对简答 QA 极有效**。让模型先"猜一个答案"，把"问题 + 猜答案"一起检索，对填空式题型召回提升明显。

7. **重排序的边际收益**。DashVector top-k 召回后用 Qwen-VL 当 reranker 重新打分（"这段是否能回答问题"），top-30 → top-5 的过滤能显著降噪。需评估其额外推理耗时是否值得。

8. **模型只能加载一次**。50 题循环之前必须先 `model = load_once()`，否则单题耗时会爆炸。
